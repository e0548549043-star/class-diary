# 📘 מדריך API לכתיבת צד ה־React

המסמך הזה מתאר **כל מה שצריך לדעת על השרת** כדי לכתוב את צד ה־React בעצמך: כתובות, מה שולחים, מה מקבלים, הרשאות ושגיאות.
אין כאן קוד React – רק תיאור של התקשורת עם השרת.

> 💡 אפשר לנסות כל קריאה בעצמך ב־Swagger: `<BASE_URL>/api-docs`. שם יש גם דוגמאות מלאות.

---

## 1. כתובת השרת (Base URL)

| סביבה | Base URL |
|---|---|
| שרת בענן (Render) | `https://<שם-השרת-שלך>.onrender.com` |
| שרת על המחשב | `http://localhost:3000` |

כל הכתובות במדריך מתחילות ב־`/api`. למשל, התחברות = `POST https://...onrender.com/api/auth/login`.

💡 מומלץ לשמור את ה־Base URL במקום אחד בפרויקט (למשל משתנה סביבה של Vite בשם `VITE_API_URL`) ולא לכתוב אותו בכל קובץ.

⚠️ כדי שהדפדפן יסכים לפנות לשרת, הכתובת של ה־React (למשל `http://localhost:5173`) חייבת להופיע במשתנה `CORS_ORIGIN` בשרת.

## 2. התחברות (Authentication)

### איך זה עובד
1. המשתמש מקליד ת.ז וסיסמה ← שולחים `POST /api/auth/login`.
2. השרת מחזיר **token** (JWT) ופרטי המשתמש, כולל התפקיד (`role`).
3. שומרים את ה־token בצד הלקוח (למשל ב־`localStorage`).
4. **בכל קריאה אחרת** לשרת שולחים את ה־token בכותרת (Header).
5. התוקף: 8 שעות. אחרי זה השרת מחזיר 401 ← מוחקים את ה־token ומעבירים למסך התחברות.
6. התנתקות = פשוט למחוק את ה־token מהלקוח (אין קריאה לשרת).

### איך שולחים Bearer Token
בכל בקשה מוגנת מוסיפים את הכותרת:
```
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```
המילה `Bearer`, רווח אחד, ואז ה־token. בבקשות עם גוף (POST / PUT / PATCH) מוסיפים גם:
```
Content-Type: application/json
```

### בקשת התחברות
```http
POST /api/auth/login
Content-Type: application/json

{ "idNumber": "200000008", "password": "Demo1234!" }
```
תשובה **200**:
```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "tokenType": "Bearer",
  "expiresIn": "8h",
  "user": {
    "id": 2,
    "idNumber": "200000008",
    "firstName": "רבקה",
    "lastName": "פרידמן",
    "role": "TEACHER",
    "class": null
  }
}
```
שגיאות: **400** שדה חסר · **401** ת.ז או סיסמה שגויים · **429** יותר מדי ניסיונות (20 ב־15 דקות).

### לאן לנתב אחרי התחברות (לפי `user.role`)
| role | מסך פתיחה |
|---|---|
| `ADMIN` | רשימת כיתות (מנהל) |
| `TEACHER` | רשימת כיתות (מורה) |

### מי מחובר עכשיו? (לרענון דף)
```http
GET /api/auth/me
Authorization: Bearer <token>
```
מחזיר את אותו אובייקט `user` כמו בהתחברות. אם חוזר **401** – ה־token לא בתוקף ← למסך התחברות.

## 3. מבני הנתונים

### User (משתמש)
```json
{
  "id": 41,
  "idNumber": "300000007",
  "firstName": "שרה",
  "lastName": "אברהמי",
  "role": "STUDENT",
  "class": { "id": 5, "name": "ט'1" }
}
```
- `role`: ‏`ADMIN` (מנהל) / `TEACHER` (מורה) / `STUDENT` (תלמיד)
- `class`: רק לתלמיד; למורה ולמנהל `null`

### StudentStats (אחוזים של תלמיד)
```json
{
  "schoolYearStart": "2026-09-01",
  "totalLessons": 120,
  "present": 110,
  "late": 4,
  "absent": 6,
  "attendancePercent": 93.3
}
```
- **אחוז נוכחות** = (נכח + חצי מהאיחורים) ÷ כל השיעורים × 100
- מתחילת שנת הלימודים (1 בספטמבר). אם אין עדיין נתונים – `null` (כדאי להציג "—").

### Lesson (שיעור – מלא)
```json
{
  "id": 812,
  "date": "2026-10-14",
  "lessonNumber": 2,
  "topic": "שברים פשוטים - חיבור וחיסור",
  "class": { "id": 5, "name": "ט'1" },
  "subject": { "id": 7, "name": "מתמטיקה" },
  "teacher": { "id": 2, "firstName": "רבקה", "lastName": "פרידמן" },
  "attendanceSummary": { "present": 20, "late": 2, "absent": 1 },
  "attendance": [
    { "studentId": 41, "firstName": "שרה", "lastName": "אברהמי", "status": "PRESENT" },
    { "studentId": 42, "firstName": "מרים", "lastName": "ברגר", "status": "LATE" },
    { "studentId": 43, "firstName": "חנה", "lastName": "גולד", "status": "ABSENT" }
  ]
}
```
| שדה | משמעות |
|---|---|
| `date` | תאריך בפורמט `YYYY-MM-DD` |
| `lessonNumber` | מספר השיעור ביום (1–10) |
| `topic` | מה נלמד |
| `status` | `PRESENT` נכח · `LATE` איחר · `ABSENT` חסר |
| `attendance` | ממוין לפי שם משפחה |

### Page (רשימה בעמודים)
רשימות ארוכות חוזרות בעמודים:
```json
{ "items": [ ... ], "page": 1, "pageSize": 20, "total": 87, "totalPages": 5 }
```
שולחים `?page=2&pageSize=20` כדי לקבל עמוד אחר (`pageSize` עד 100).

## 4. רשימת ה־Endpoints

🔓 = ציבורי · 🔒 = דורש token

| Method | URL | מי מורשה | מה עושה |
|---|---|---|---|
| GET | `/api/health` | 🔓 כולם | בדיקה שהשרת פועל |
| POST | `/api/auth/login` | 🔓 כולם | התחברות |
| GET | `/api/auth/me` | 🔒 כל מחובר | המשתמש המחובר |
| GET | `/api/subjects` | 🔒 כל מחובר | רשימת מקצועות |
| GET | `/api/classes` | 🔒 מנהל, מורה | רשימת כיתות |
| GET | `/api/classes/:classId/students` | 🔒 מנהל, מורה | תלמידי כיתה |
| GET | `/api/classes/:classId/lessons` | 🔒 מנהל, מורה | יומן כיתה (מורה: רק השיעורים שלו) |
| POST | `/api/lessons` | 🔒 מורה | פתיחת שיעור להיום |
| GET | `/api/lessons/:id` | 🔒 מנהל, מורה (רק שלו) | שיעור בודד |
| PUT | `/api/lessons/:id` | 🔒 מורה (רק שלו) | עריכת שיעור |
| GET | `/api/users` | 🔒 מנהל | רשימת משתמשים + חיפוש וסינון |
| GET | `/api/users/:id` | 🔒 מנהל | משתמש בודד |
| PATCH | `/api/users/:id/password` | 🔒 מנהל | איפוס סיסמה |

## 5. מסך אחר מסך – אילו קריאות צריך

### מסך 1: התחברות (מנהל ומורה)
- `POST /api/auth/login`
- **שדות חובה בטופס:** ת.ז (`idNumber`), סיסמה (`password`).
- הצגת שגיאה: את `error.message` מהתשובה (כבר בעברית).

---

### מסך 2: רשימת כיתות (מנהל ומורה)
```http
GET /api/classes
```
תשובה – מערך, ממוין לפי שכבה:
```json
[
  { "id": 1, "name": "ז'1", "gradeLevel": 7, "studentCount": 22 },
  { "id": 2, "name": "ז'2", "gradeLevel": 7, "studentCount": 24 }
]
```
לחיצה על כיתה ← מסך 3 או מסך 6 (מנהל), או מסך 4 (מורה).

---

### מסך 3: יומן כיתה – צפייה (מנהל)
```http
GET /api/classes/5/lessons?page=1&pageSize=20
GET /api/classes/5/lessons?subjectId=7          ← סינון לפי מקצוע
GET /api/subjects                                ← לרשימת הבחירה של הסינון
```
- תשובה: **Page** של **Lesson**, ממוין מהתאריך החדש לישן, ובתוך כל יום לפי מספר שיעור.
- **קיבוץ לפי ימים:** השיעורים מגיעים ברצף; לקבץ אותם בצד הלקוח לפי השדה `date`.
- לכל שיעור יש `attendanceSummary` (לתצוגה מקוצרת) ו־`attendance` (לפירוט מלא).

---

### מסך 4: השיעורים שלי בכיתה (מורה)
```http
GET /api/classes/5/lessons?page=1&pageSize=20
GET /api/classes/5/lessons?subjectId=7
GET /api/subjects
```
- אותה כתובת כמו אצל המנהל – אבל **השרת מחזיר למורה רק את השיעורים שהוא לימד**. אין צורך לסנן בעצמך.
- כפתור "פתיחת שיעור להיום" ← מסך 5 במצב הוספה.
- כפתור "עריכה" בכל שיעור ← מסך 5 במצב עריכה.

---

### מסך 5: פתיחה / עריכה של שיעור (מורה)

**טעינת נתונים לטופס:**
```http
GET /api/subjects                        ← רשימת מקצועות לבחירה
GET /api/classes/5/students              ← (בפתיחה) התלמידים לטבלת הנוכחות
GET /api/lessons/812                     ← (בעריכה) השיעור הקיים
```
תשובת `students` – ממוינת לפי שם משפחה:
```json
[
  { "id": 41, "idNumber": "300000007", "firstName": "שרה", "lastName": "אברהמי" },
  { "id": 42, "idNumber": "300000015", "firstName": "מרים", "lastName": "ברגר" }
]
```
בעריכה, רשימת התלמידים לקוחה מ־`attendance` של השיעור הקיים (ולא מרשימת הכיתה).

**שדות הטופס:**

| שדה | חובה | כללים |
|---|:-:|---|
| `subjectId` | ✅ | `id` מתוך רשימת המקצועות |
| `lessonNumber` | ✅ | מספר שלם 1–10 |
| `topic` – מה נלמד | ✅ | 1–1000 תווים |
| `attendance` | ✅ | שורה לכל תלמיד – **כל** התלמידים, כל אחד **פעם אחת** |
| `attendance[].studentId` | ✅ | `id` מתוך רשימת התלמידים |
| `attendance[].status` | ✅ | `PRESENT` / `LATE` / `ABSENT` |

⚠️ אסור לשלוח שדות נוספים (בגוף הבקשה או בשורות הנוכחות) – שדה לא מוכר מחזיר **400**.

**שמירה – פתיחת שיעור:**
```http
POST /api/lessons
Authorization: Bearer <token>
Content-Type: application/json

{
  "classId": 5,
  "subjectId": 7,
  "lessonNumber": 3,
  "topic": "שברים פשוטים - חיבור וחיסור",
  "attendance": [
    { "studentId": 41, "status": "PRESENT" },
    { "studentId": 42, "status": "LATE" },
    { "studentId": 43, "status": "ABSENT" }
  ]
}
```
- **התאריך וזהות המורה נקבעים בשרת** (היום, לפי שעון ישראל, והמורה המחובר) – לא שולחים אותם.
- הצלחה: **201** + ה־**Lesson** שנוצר.

**שמירה – עריכת שיעור:**
```http
PUT /api/lessons/812
```
אותו גוף כמו בפתיחה, **בלי** `classId` (אי אפשר לשנות כיתה או תאריך). הצלחה: **200** + ה־**Lesson** המעודכן.

**שגיאות אפשריות:**
| קוד | מתי |
|---|---|
| 400 | שדה חסר/שגוי, שדה לא מוכר, חסר תלמיד בנוכחות, תלמיד מכיתה אחרת (ב־`error.details` יש פירוט לכל שדה) |
| 403 | עריכת שיעור של מורה אחר |
| 404 | השיעור לא קיים |
| 409 | מספר השיעור כבר תפוס באותה כיתה באותו יום |

---

### מסך 6: תלמידי כיתה ורשימת מורים (מנהל)
```http
GET /api/users?role=STUDENT&classId=5&pageSize=100   ← תלמידי כיתה, עם אחוז נוכחות
GET /api/users?role=TEACHER&pageSize=100             ← רשימת המורים
GET /api/users/41                                    ← משתמש בודד
```
- תשובה: **Page** של משתמשים. לכל משתמש יש שדה `stats`:
  - לתלמיד: אובייקט **StudentStats** ← עמודת "% נוכחות" (`stats.attendancePercent`).
  - למורה ולמנהל: `null`.
- אפשר גם `search` – כל מילה צריכה להופיע בשם הפרטי, בשם המשפחה או בתחילת הת.ז (למשל "שרה אברהמי" מוצא את שרה אברהמי).
- מיון: לפי שם משפחה.

**איפוס סיסמה** (המנהל מקליד סיסמה חדשה, לתלמיד או למורה):
```http
PATCH /api/users/41/password

{ "password": "NewPass123" }
```
הצלחה: **200** `{ "message": "הסיסמה אופסה בהצלחה" }`. שגיאות: **400** (סיסמה קצרה מ־6 או ארוכה מ־72 תווים), **404** (משתמש לא קיים).

## 6. שגיאות

כל שגיאה חוזרת באותו מבנה:
```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "הנתונים שנשלחו אינם תקינים",
    "details": [
      { "field": "topic", "message": "יש לכתוב מה נלמד בשיעור" },
      { "field": "attendance.2.status", "message": "סטטוס נוכחות חייב להיות PRESENT (נכח), LATE (איחר) או ABSENT (חסר)" }
    ]
  }
}
```
- `message` – בעברית, אפשר להציג ישירות למשתמש.
- `details` – רק בשגיאות 400; `field` הוא שם השדה בטופס (ברשימות: `attendance.2.status` = השורה השלישית, כי מתחילים מ־0). שימושי להצגת שגיאה ליד כל שדה.

| קוד HTTP | `code` | מתי | מה לעשות בלקוח |
|---|---|---|---|
| 400 | `VALIDATION_ERROR` | נתונים לא תקינים | להציג את השגיאות ליד השדות |
| 401 | `UNAUTHORIZED` | אין token / לא תקין / פג תוקף / ת.ז או סיסמה שגויים | למחוק token ולעבור להתחברות |
| 403 | `FORBIDDEN` | אין הרשאה לפעולה | להציג הודעה; לא אמור לקרות אם מסתירים כפתורים לפי תפקיד |
| 404 | `NOT_FOUND` | הרשומה לא קיימת | להציג "לא נמצא" |
| 409 | `CONFLICT` | מספר שיעור תפוס | להציג את `message` |
| 429 | `TOO_MANY_REQUESTS` | יותר מדי ניסיונות התחברות | לבקש לנסות שוב מאוחר יותר |
| 500 | `INTERNAL_ERROR` | תקלה בשרת | הודעה כללית |

## 7. מה מוחזר בהצלחה – סיכום

| פעולה | קוד | גוף התשובה |
|---|---|---|
| התחברות | 200 | `{ token, tokenType, expiresIn, user }` |
| קריאת רשימה בעמודים | 200 | `{ items, page, pageSize, total, totalPages }` |
| קריאת רשימה פשוטה (כיתות, מקצועות, תלמידי כיתה) | 200 | מערך |
| קריאת פריט | 200 | הפריט |
| יצירה (שיעור) | **201** | הפריט שנוצר |
| עדכון (שיעור) | 200 | הפריט אחרי העדכון |
| איפוס סיסמה | 200 | `{ message }` |

## 8. הרשאות – סיכום לתכנון המסכים

| | מנהל | מורה |
|---|:-:|:-:|
| רשימת כיתות | ✅ | ✅ |
| יומן כיתה מלא | ✅ | ❌ |
| השיעורים שלי בכיתה | — | ✅ |
| פתיחה ועריכה של שיעור | ❌ | ✅ (רק שלו) |
| תלמידי כיתה עם אחוז נוכחות, רשימת מורים, איפוס סיסמה | ✅ | ❌ |

💡 כדאי להסתיר בממשק כפתורים ומסכים שהמשתמש לא מורשה אליהם – אבל ההגנה האמיתית היא בשרת, שבודק כל בקשה.

## 9. חשבונות לבדיקה

הסיסמה של כולם = הערך של `SEED_PASSWORD` שהוגדר בשרת.

| תפקיד | ת.ז |
|---|---|
| מנהל | `100000009` |
| מורה (מתמטיקה) | `200000008` |

ביום הנוכחי מתועדים מראש רק שיעורים 1–2 בכל כיתה – אפשר לפתוח שיעור 3 ומעלה.
